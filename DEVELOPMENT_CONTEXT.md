## Как устроено приложение

Приложение маскирует защищённое хранилище под системный калькулятор. Калькулятор доступен без входа; вход в хранилище скрыт за обычным вводом PIN/кода в калькуляторе и отдельными сценариями Action Button. Основные подсистемы разделены по каталогам `Sources/SecureVault`.

### `App`

- `SecureVaultApp.swift` — корневой SwiftUI App, жизненный цикл сцены, privacy cover, обработка Action Button URL, запуск/остановка таймеров, обработка холодного старта и protected-data lock.
- `VaultAccessView.swift` — первый setup PIN и обычная разблокировка.
- `VaultLifecycle.swift` — состояние удаления/сброса, поколения доступа, маркеры в Application Support, `VaultGate`.
- `SettingsView.swift` — настройки приложения и безопасности.
- `WelcomeGuideView.swift` — руководство, которое предлагается после создания PIN и доступно из настроек.
- `BruteForceConfirmationView.swift` — подтверждение и 15-секундная задержка перед включением «Защиты от перебора пароля».
- `InactivityConfirmationView.swift` — подробное подтверждение Dead Man’s Switch с 15-секундной задержкой.

### `Calculator`

- `CalculationEngine.swift` — разбор и вычисление выражений, приоритеты, скобки, научные операции.
- `CalculatorViewModel.swift` — ввод, история, память, научные режимы, скрытая проверка PIN, лимит неверных вводов.
- `CalculatorView.swift` — стандартный/научный/конверсионный UI и анимации кнопок.
- `ConversionModel.swift` — единицы и валюты. Валютные курсы загружаются из Frankfurter по HTTPS, кэшируются в `UserDefaults`; в коде есть статическая подпись `Обновлено: 1 час назад`, а фактический статус курса также может показывать дату ответа Frankfurter.

Математические заметки из оригинального калькулятора намеренно не реализуются и не должны возвращаться без отдельного решения пользователя.

### `Camera`

- `CameraViewModel.swift` — AVFoundation, виртуальные камеры, плавный zoom, вспышка, серии снимков, расстояние между событиями, pending event.
- `CameraScreen.swift` — экран камеры, GPS/азимут, блокировки точности и OSM, режим чёрного экрана, кнопки съёмки и громкости.
- `CameraView.swift` — `PreviewView` с `AVCaptureVideoPreviewLayer` и нативным слоем прицела.
- `CrosshairView.swift` — старый SwiftUI-компонент; фактический прицел камеры теперь рисуется в `PreviewView`, чтобы не зависеть от высоты панелей интерфейса.
- `WatermarkRenderer.swift` — впечатывает координаты, точность, азимут, шаблон, аватар и прицел в экспортируемую копию.

Важное решение по прицелу: прицел должен находиться в центре исходного кадра. Панель координат сверху является наложением поверх фото, а шаблон/аватар добавляются отдельным footer снизу. Нельзя вписывать фото в общий прямоугольник вместе с footer: это растягивает или сжимает исходные 4:3/3:4 пропорции.

### `Editor`

- `PhotoEditorView.swift` и `GalleryEditorView.swift` — редактор фото.
- `DrawingCanvas.swift` — стрелки, овалы, текст, размытие.
- Текст должен двигаться одним пальцем, масштабироваться и вращаться двумя пальцами, иметь настраиваемый фон и выглядеть близко к Telegram.
- Разметка и размытие впечатываются в сохранённую копию; оригинал не должен портиться.

### `Storage`

- `FileStorageManager.swift` — зашифрованные JPEG, зашифрованные sidecar JSON, серии/события, папки режимов, номера, перенос и удаление.
- `CaptureContext` связывает кадры одного события: `eventID`, папка, ожидаемое количество кадров, индекс кадра, номер события и поколение доступа.
- `PhotoMeta` содержит GPS, дату, заметку, event ID/index/count, номера и папку.
- Сохранение фото теперь транзакционное: создаётся `.jpg.pending`, затем JPEG, sidecar и anchor; удаление pending-файла коммитит пару. При сбое или force quit незавершённая пара откатывается при следующем запуске.
- `.last-event` — малый anchor, зашифрованный camera key. Он хранит только координату первого кадра последнего события и позволяет проверять расстояние в camera-only режиме без открытия галереи.
- При полном PIN unlock anchor пересобирается; после удаления фото он также пересобирается, чтобы не ссылаться на удалённое событие.
- Событие из двух фото имеет одну координату: координата берётся с первого кадра. Минимальная дистанция применяется между событиями, а не между кадрами одного события.
- `NotesManager.swift` — зашифрованный дневник.
- `SettingsStore.swift` — настройки UI, protected preferences, режимы, папки, серии, Action Button, безопасность.

### `Utils`

- `CryptoManager.swift` / `VaultCipher` — AES-GCM и PIN binding.
  - Основной master key привязан к PIN через Keychain PIN envelope.
  - После binding raw master key удаляется.
  - Camera key отдельный: он нужен ограниченной камере Action Button для фото, аватара, шаблонов и pending event; он не открывает галерею/дневник.
  - Старый баг с созданием нового raw key рядом с PIN envelope закрыт. При правильном PIN старый случайно созданный raw key может быть упакован как recovery key, чтобы спасти уже существующие файлы.
- `ProtectedPreferences.swift` — шифрует историю калькулятора, шаблоны, аватар и pending event; camera-scoped значения могут читаться camera-only.
- `KeychainCodeStore.swift` — коды, лимиты перебора, cooldown, Action Button token и миграционные маркеры.
- `MainPINChangeTransaction.swift` — журнал смены основного PIN. Сначала пишется pending journal, затем меняются PIN envelope и `mainCode`; незавершённая транзакция восстанавливается при запуске.
- `InactivityTimerManager.swift` — Dead Man’s Switch. Состояние v2 хранит атомарную Keychain-запись с лимитом, wall clock и system uptime; старые три записи читаются для миграции.
- `PhotoExporter.swift`, `ZipExporter.swift`, `ExportMetadata.swift` — JPEG/ZIP экспорт, очистка временных файлов, выбор метаданных.
- `BlackScreenGesture.swift` — тройное двойное касание в камере.
- `VolumeButtonHandler.swift` — съёмка кнопками громкости.

### `Location`

- `LocationManager.swift` — GPS, heading, разрешения и обновление координат.
- `RestrictedPlaces.swift` — категории зон, классификация OSM-тегов, расстояние до точки/границы, политика блокировки.
- `RestrictedPlacesMonitor.swift` — онлайн Overpass, кэш, автоматический режим, таймер проверки и сообщения камеры.
- `RestrictedPlaceIndex.swift` — spatial index для локальной базы, включая крупные территории.
- `OSMPBFPlaceParser.swift` — разбор региональных OSM PBF, multipolygon, relation/site, dense nodes и геометрии.
- `OfflineRegion.swift` — каталог регионов, dataset schema/source, coverage и безопасная миграция старых индексов.
- `OfflineMapManager.swift` / `OfflineMapsView.swift` — скачивание MapLibre-карт и объектов зон, progress/log, checkpoint/resume.
- `RestrictedPlacesSettingsView.swift` — настройки включения контроля, режима online/offline/automatic, категорий, радиусов и требования блокировать при пустом ответе.
- `OpenStreetPhotoMap.swift` — просмотр фотографий на MapLibre/карте.

## OSM: принятые правила

Контроль зон предназначен для РФ/СНГ и использует OpenStreetMap/Overpass, но регион пользователя не зашит в приложение. В каталоге есть регионы России и других территорий; Кировская область присутствует как обычный элемент каталога, это не пользовательский профиль.

### Категории и радиусы

`RestrictedPlaceKind` содержит: детские площадки, детские сады, школы, спортплощадки, полиция/МВД, силовые службы/ФСБ, администрации, суды, прокуратуры, военкоматы, военные территории и прочие госучреждения. По умолчанию детские категории — 65 м, государственные/силовые — 100 м; значения настраиваются.

Проверка учитывает расстояние до границы территории, а не до центра полигона. Плохая/устаревшая GPS-точность, отсутствие свежих координат и отсутствие проверяемого покрытия блокируют съёмку, если контроль включён. Пустой онлайн-ответ разрешает съёмку по текущей пользовательской настройке `blockOnEmptyOnlineResponse` (по умолчанию — разрешить).

### Режимы

- **Онлайн** — запрос к мировому Overpass, карту скачивать не нужно.
- **Офлайн** — используется полностью загруженный и проверенный региональный dataset.
- **Автоматически** — сначала ждёт актуальный онлайн-ответ; старый офлайн snapshot не показывается во время первого запроса. Офлайн используется как резерв после фактической ошибки сети.

Пользователь принял решение не добавлять отдельный медленный онлайн-запрос `is_in` для случаев, когда человек находится глубоко внутри большой территории, но её граница дальше радиуса запроса. Для таких территорий нужно использовать проверенные офлайн-контуры. Это осознанное ограничение быстрого онлайн-режима.

### Что было исправлено в OSM

- Удалено швейцарское зеркало `overpass.osm.ch`, которое могло вернуть корректный пустой ответ для РФ.
- Убран Unicode/Cyrillic regex из Overpass-запросов: некоторые серверы отвечали HTTP 400. Теперь запрашиваются existence-фильтры `name`, `name:ru`, `operator`, `operator:ru`, `official_name`, а русская классификация выполняется локально.
- Исправлены неполные/сломанные multipolygon и relation, пустые роли, node/site relations, обрезанные PBF и переполнения delta-varint.
- Resume PBF теперь требует ETag/Last-Modified и проверяет Content-Range, чтобы не склеивать разные версии файла.
- Старые zone indexes без `schemaVersion/source` больше не считаются доказанно полными; они требуют обновления. Файлы карт и пользовательские фото при этом не удаляются.

### Проверенная точка пользователя

В ходе аудита был проверен live OSM район около `58.599612, 49.684514`. В актуальной выгрузке не обнаружена площадка в 60 м; ближайшая размеченная площадка была примерно в 264 м. Физический объект, отсутствующий в OSM, по принятому решению не считается проблемой приложения и не должен приводить к попытке «угадать» нарушение.

## Безопасность и жизненный цикл

### PIN и ключи

- Первое открытие после установки/полного reset должно показывать setup основного PIN.
- Неверный PIN проходит cooldown/счётчик. «Защита от перебора пароля» настраивается в количестве попыток.
- После достижения лимита используется тихая блокировка: публичный UI остаётся обычным калькулятором, без сообщения «хранилище заблокировано» и без восстановления долгим удержанием. Файлы и ключи стираются, внутренний marker не позволяет создать новый PIN в том же контейнере.
- Face ID добавлять не нужно: пользователь сознательно отказался от него из-за риска принудительного разблокирования лицом.
- Jailbreak не входит в основной threat model.

### Dead Man’s Switch

Доступны `Выключено`, 24, 48, 72 часа и 7 дней. Счётчик обновляется после успешной разблокировки хранилища. Проверяются абсолютное время и `ProcessInfo.systemUptime`; откат часов или подозрительное несоответствие может привести к немедленному сбросу. Предупреждение специально говорит не играть с системным временем. Включение требует подробного текста и 15 секунд ожидания.

DMS проверяется при холодном старте и при возвращении приложения в active scene. iOS не гарантирует фоновый запуск ровно в момент истечения срока, поэтому проверка выполняется при следующей возможности. Нельзя менять DMS-семантику или заменять уничтожение блокировкой без отдельного решения пользователя.

### Action Button

Поддержаны `Выключено`, открытие камеры, удаление фото, полный reset и полное стирание с reset входа. Destructive URL получает случайный token в Keychain; старый camera URL не становится destructive-командой. Камера через Action Button ограничена: она не должна открывать галерею или дневник.

## Экспорт и Telegram

- JPEG экспорт очищает встроенные EXIF/GPS при включённой очистке и сохраняет исходное соотношение сторон.
- Footer с координатами/подписью/аватаром добавляется снизу; исходное фото не растягивается.
- `ArchiveMetadataOptions` поддерживает отдельные поля: координаты, дату, папку, событие, нумерацию, заметки, ссылку на карту, а также режим «только координаты».
- Координаты округляются до 6 знаков.
- Для события используется координата первого кадра.
- Telegram передаётся через системный Share Sheet без токена бота. Принимающее приложение может разложить текст и альбом по-своему; приложение не может гарантировать, что подпись станет одним альбомным сообщением.
- Длинные списки координат режутся на сообщения до примерно 3800 символов.

## История принятых продуктовых решений

- Интерфейс — тёмный, визуально близкий к калькулятору iPhone: чёрный фон, серые кнопки, оранжевые операции, системный шрифт, системные анимации.
- Название на устройстве — `Калькулятор`; значок — стилизация под настоящий Apple Calculator.
- Пользователь предпочитает задавать уточняющие вопросы перед спорными изменениями, а не переделывать функциональность многократно.
- Не добавлять ненужные «улучшения ради идеального кода». Сначала подтверждать воспроизводимый дефект.
- Не передавать покупателю исходный код и не добавлять в production-ресурсы личные фото, шаблоны, локальные пути Windows, имя пользователя или тестовые пользовательские данные.
- Репозиторий и история предназначены для разработки; перед передачей покупателю нужен только IPA/оговорённый пакет.
- Пользователь сам тестирует IPA через ESign.

## Известные ограничения и незавершённые задачи

1. **GitHub Actions не подтверждает текущую сборку.** Последние workflow завершились до запуска runner из-за проблем с оплатой/лимитом аккаунта. После исправления billing нужно запустить `.github/workflows/main.yml`, дождаться unit/UI tests и Release IPA.
2. **iOS-тесты не запускались локально.** Windows-среда не содержит Xcode, поэтому текущий commit нельзя объявлять полностью проверенным до macOS CI.
3. **Большая онлайн-территория за пределами радиуса запроса.** По решению пользователя дополнительный `is_in` online-запрос не добавляется; для этого нужны офлайн-контуры.
4. **Полнота OSM зависит от самой карты.** Если объект отсутствует в OSM, приложение не должно его угадывать. Это принятое ограничение, а не задача на ML/геолокационную эвристику.
5. **Реальный iPhone smoke test обязателен.** Особенно проверить iPhone 17 Pro/актуальную iOS, ESign, закрытие из app switcher, разрешения GPS/камеры, Action Button, сохранение при малом свободном месте и OSM на мобильной сети.
6. **Разрушительные режимы нельзя проверять на единственной рабочей установке.** Для DMS, brute-force lock и Action Button reset нужен отдельный тестовый контейнер/установка.

## Что запускать после продолжения

1. Проверить `git status` и не перезаписывать чужие незакоммиченные изменения.
2. На macOS выполнить `xcodegen generate --spec project.yml`.
3. Запустить workflow из `.github/workflows/main.yml`; сначала unit/UI tests, затем Release build и упаковку `SecureVault.ipa`.
4. После успешной сборки на iPhone проверить: первый PIN, relaunch, смену PIN, обычное фото, серию из двух кадров, force quit, footer/avatar, прицел, редактор, OSM online/automatic/offline, экспорт ZIP и Share Sheet.
5. Для OSM записывать режим, точность GPS, координаты теста, текст блокировки и сервер Overpass. Не считать физический, но не размеченный в OSM объект дефектом алгоритма.
6. При обнаружении нового поведения сначала разделить его на подтверждённую ошибку, потенциальную проблему и субъективное пожелание. Исправлять только подтверждённое или явно согласованное пользователем.
